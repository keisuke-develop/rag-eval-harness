# セキュリティ評価記録

評価日: 2026-09-21 / 対象: `src/rageval`・`datasets`・`deploy`・CI

---

## 0. 方針

**この道具は PoC であり、評価ツールのまま維持する。**
インフラ層のセキュリティ機構（WAF・冗長化・CloudTrail による監査証跡・KMS CMK・
プライベートサブネットなど）は**意図的に外している**。判断と理由は
[00_requirements.md](00_requirements.md) の「セキュリティの範囲について」に書いた。

**一方、プログラム側のセキュリティは最低限を満たす。** 入力の扱い・秘密情報の扱い・
依存の脆弱性・静的解析は、扱うデータの機微さと関係なく必要になるため。

### 評価の前提となる、この道具の形

| 性質 | 内容 | 影響 |
|---|---|---|
| 形態 | CLI のバッチ。実験のときだけ起動して止まる | 常駐面が無い |
| 入力 | 実験ファイル（YAML）とコーパスのみ。すべてリポジトリの所有者が書く | 信頼境界を跨ぐ入力が無い |
| 通信 | 送信のみ（OpenAI API）。受信ポートを開けない | 外部から到達できない |
| データ | 公開のウィキペディア記事と検索スコア | 個人情報・決済情報を持たない |
| 利用者 | 実行する本人ひとり。認証もセッションも無い | 認証・認可・セッションの層が存在しない |

**「該当なし」と書く項目が多いが、その多くは「機能が存在しない」ためである。**
機能が無いことを確かめたうえで書いている（§1 の監査結果）。

## 1. 実施した監査

コードを読んで確かめた事実。「該当なし」の根拠になる。

| 確認したこと | 結果 |
|---|---|
| シェル実行・コード実行（`subprocess` / `os.system` / `eval` / `exec` / `pickle` / `__import__`） | `src/` に**1件も無い**。テストに `subprocess` が1件あるが、固定の引数しか渡さない（決定性の確認用） |
| YAML の読み込み | 全4箇所とも `yaml.safe_load`。`yaml.load`（任意オブジェクト生成が可能）は使っていない |
| 外部へ出る URL | `https://api.openai.com/...` の2つのみ。**定数で、設定から変更できない**（SSRF の経路が無い） |
| SQL・NoSQL クエリの組み立て | 無い。文字列連結でクエリを作る箇所が存在しない |
| XML のパース | 無い |
| 正規表現 | 6箇所。いずれも入れ子の量指定子が無く、ReDoS の形になっていない |

### 静的解析（SAST）

`ruff` に **flake8-bandit（`S` ルール）** を追加した。

```
uv run ruff check .   →  指摘 0 件
```

**ルールが実際に効いていることを、意図的に危険なコードで確認した。**
`eval()` → S307、`yaml.load()` → S506、`subprocess(shell=True)` → S602 を検出。
「0件」が「検査していない」ではないことを確かめてある。

### 依存ライブラリの脆弱性（SCA）

`pip-audit` を CI に追加した。**最初の実行で5件見つかった。**

| パッケージ | 件数 | 内容 | 修正版 |
|---|---|---|---|
| chromadb 1.5.9 | 5 | 認証前のコード実行、認可バイパスなど | **存在しない**（1.5.9 が最新） |

いずれも ChromaDB の**サーバ機能**の脆弱性で、この道具は `EphemeralClient` を
プロセス内で使うだけなので到達経路は無い。ただし、

- **どの実験でも使っていない**（すべて `store.kind: memory`）
- 依存だけで60以上のパッケージを引き込む

ため、**既定の依存から外して任意インストールにした**（`uv sync --extra chroma`）。
`VectorStore` の差し替え点（ADR 0002）は残っている。

| | 対応前 | 対応後 |
|---|---|---|
| インストールされるパッケージ | 103 | **50** |
| 既知の脆弱性 | 5 | **0** |

あわせて実験ファイルの `store.kind` を `memory` に揃えた。
近似最近傍のぶれが条件の差に混ざらないほうが、比較の道具として素直なため。

### 規模の限界（実測）

コーパスを複製して倍率を上げ、索引の時間・1問あたりの検索時間・ベクトルのメモリを測った。

| 倍率 | 文書 | チャンク | 索引 | 1問あたり | ベクトルのメモリ |
|---|---|---|---|---|---|
| 1x | 12 | 137 | 0.5秒 | 0.1ms | 3MB |
| 5x | 60 | 685 | 2.7秒 | 0.3ms | 16MB |
| 20x | 240 | 2,740 | 10.8秒 | 0.9ms | 62MB |
| 50x | 600 | 6,850 | 27.3秒 | 2.8ms | 155MB |

いずれもチャンク数に対して線形。ここから外挿すると、

- **メモリが先に効く。** 手元（8GB 使えるとして）で約 35,000 文書、**AWS の Fargate 1GB 設定では約 4,000 文書**
- 時間は問題にならない。1,000文書でも索引45秒・検索5ms 程度
- **評価セットを増やす側のコストはほぼゼロ。** 1問 0.1ms なので、53問を500問にしても実行時間は変わらない

メモリを食っているのは埋め込みを Python の float のリストで持っているところ（1チャンク23KB。
float32 の配列なら2KB で足りる）。いまの規模では割に合わないので直していないが、
**コーパスを数千文書に増やすときは、ここが最初に効く。**

## 3. 脅威モデルと、受け入れた残リスク

### 誰が何を狙えるか

| 攻撃者 | 到達経路 | 評価 |
|---|---|---|
| ネットワーク上の第三者 | **無い。** 受信ポートを開けず、公開エンドポイントも持たない | 到達不能 |
| コーパス・評価セットを細工できる者 | リポジトリへのコミット権が要る | コミット権がある時点でコード自体を変えられるので、追加のリスクにならない |
| 実験ファイルを書ける者 | 任意のパスを読ませられる（Path Traversal） | 実行者自身なので信頼境界を跨がない |
| 依存ライブラリの供給元 | ロックで版とハッシュを固定 | 固定済み。取り込み時のレビューが最後の砦 |
| AWS の同一アカウント利用者 | IAM で限定 | タスクは `runs/*` にしか書けない |

### 受け入れたリスク

| リスク | 判断 |
|---|---|
| ベースイメージの CVE（CRITICAL 4 / HIGH 14） | **受容すると判断した**（下記） |
#### ベースイメージの CVE を受容する判断

全件が OS パッケージ（perl 7件・openssl 4件・util-linux 5件・zlib 1件ほか）由来で、
このリポジトリのコードからは1件も出ていない。
`apt-get upgrade` を当てたが**1件も減らなかった**（Debian bookworm に修正版がまだ無い）。

受容の根拠は3つある。**いずれかが崩れたら、この判断を取り下げること。**

| 根拠 | いま成り立っている理由 | 崩れるとき |
|---|---|---|
| **扱うのは公開文書だけ** | コーパスはウィキペディアの記事、出力は検索スコアと引用文。奪われて困るものがイメージの中に無い | 社内文書や個人情報をコーパスに入れたとき |
| **受信ポートが無い** | ECS の RunTask で起動するバッチで、公開エンドポイントを持たない。外部から到達できない | サービス化して受け口を開けたとき |
| **1回で消える** | タスクは実験1本ぶんを回して終了し、ストレージも破棄される。居座られる先が無い | 常駐させたとき |

減らす手段は distroless / Chainguard 系への変更だが、シェルが無くなるので
`deploy/entrypoint.sh` を書き直すことになる。いまの用途では見合わないと判断した。

OS のセキュリティ更新は、減らなかったからといって Dockerfile から外さない。
修正版が出た時点で自動的に入るようにしておくため（`Dockerfile` のコメントに理由を書いてある）。

| リスク | 判断 |
|---|---|
| Path Traversal を制限していない | 実験ファイルを書くのは実行者自身。制限を入れるとテストや別ディレクトリでの実行が壊れる |
| メモリ上限を設けていない | いまの規模では問題にならない。将来コーパスを大きくするなら再検討 |
| 秘密の自動ローテーションが無い | PoC。鍵は手作業で入れ替える |

## 4. checkov が指摘し、理由をつけて見送った5件

スキャナを黙らせるのではなく、**テンプレートに1件ずつ理由を書いて抑止**している。
理由が読めない抑止は、次に読む人にとって無いのと同じなので。

| チェック | 対象 | 見送った理由 |
|---|---|---|
| CKV_AWS_18 | S3 アクセスログ | 別バケットが要る。置くのは公開文書の検索スコアだけで、誰がいつ読んだかを追う必要が無い |
| CKV_AWS_136 | ECR の KMS 暗号化 | CMK は鍵あたり月 $1 + API 課金。イメージに秘密を入れていない（鍵は実行時に SSM から渡す）ので AES256 で足りる |
| CKV_AWS_158 ×2 | ロググループの KMS 暗号化 | ログに秘密情報を書かない方針。CMK の常時課金に見合わない |
| CKV_AWS_65 | Container Insights | CloudWatch のメトリクス課金が乗る。1回きりのバッチで見る指標が無い |

**5件とも「PoC だから外す」と決めたカテゴリに収まっている**（[00_requirements.md](00_requirements.md)）。
方針を本番水準に変えるなら、真っ先に外すべき抑止がこの5件になる。

## 5. この評価の限界

- **攻撃を試していない。** 設定とコードを読んだ評価であり、ペネトレーションテストではない
- **アカウント全体の設定を見ていない。** CloudTrail・GuardDuty・Config・ルートアカウントの MFA などは
  この道具が作るものの外にあり、今回は「既存リソースに一切触れない」方針だったため確認もしていない
- **一時点の評価である。** 依存も CVE も日々変わる。`pip-audit` を CI に入れたので
  依存は継続的に見えるが、OS パッケージとベースイメージは push 時にしか見ていない
