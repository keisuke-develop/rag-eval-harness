# ADR 0004: 条件を比べる前に、測定系の分解能を測る

- 状態: 採用
- 日付: 2026-09-21

## 背景

実験001〜006 を回し終えたあとで、結果の読み方そのものが疑わしくなった。

実験002（重複幅）で「重複を入れたら Recall が下がった」という結果が出た。個別の質問を追うと、正解チャンクが**内容の8割が同じ別チャンクにずれただけ**で、2位から5位圏外に落ちていた。条件が効いたのではなく、チャンク境界がたまたま質問に有利／不利な位置に来ていた。

そこで `chunk.phase`（境界の位置をずらすだけの自由度。分割の粗さも重複幅も変えないので、本来スコアに意味のある影響を与えてはいけない）を足して測った。

| 指標 | 条件を何も変えずに出る散らばり |
|---|---|
| Recall@5 | 0.479〜0.562（幅 **0.083** = 4問） |
| MRR | 0.284〜0.385（幅 **0.101**） |

**条件を1つも変えていないのに、この幅で動いた。**

## 決定

**新しい実験群を始めるとき、最初に回すのは「条件を変えない実験」とする。**

具体的には次の2つを、比較実験より先に実施する。

1. **ノイズ幅の実測** — `chunk.phase` だけを振り、スコアがどれだけ散らばるかを測る（`experiments/offline/007_boundary_noise.yaml` の形）。
2. **検出できる差の下限の算出** — 質問ごとの当たり外れの差から標準偏差を出し、いまの評価セットの件数で検出できる差を求める（[05_offline_results.md](../05_offline_results.md) §A）。

結果は実験の記録の冒頭に置き、**それより小さい差を条件の効果として書かない。**

埋め込みモデルを実APIに差し替えるときも、これをやり直す。ノイズ幅は測定系の性質であって、一度測れば済むものではない。

## 理由

- **差の大小は、それだけでは意味を持たない。** 0.062 という差が「効いた」のか「揺れただけ」なのかは、揺れの幅を知らなければ判定できない。
- **この道具の目的は比較そのもの。** 比較の可否を左右する量を測らずに比較を始めるのは、目盛りを確認しないまま測るのと同じ。
- **後から測ると、書いた結論を取り下げることになる。** 実際に、001 の「中間に山がある」と 006 の Recall の結論を取り下げた。先に測っていれば、そもそも書かずに済んだ。

## 結果

- 実験の記録には、ノイズ幅と検出下限を先に書く。
- ノイズ幅を下回る差は「検出できない」と書く。「効果が無い」とは書かない。**測れていないだけで、無いとは言えない**ため。
- 例外として、**同じチャンク分割のうえで条件を切り替える比較**（再ランクの有無など）は、境界の運が両条件で共通して差し引きで消えるため、この幅は当てはまらない。この場合は対応のある比較として扱う（§008）。
- ただし**分割そのものが変わる比較（チャンクサイズ・重複幅）では、この例外は使えない。** 質問ごとに対応をとっても、当たる質問の顔ぶれが入れ替わるだけで、標準誤差はむしろ大きくなった（§009）。

## 検討した代替案

- **評価セットを増やして散らばりを小さくする。** 有効だが、必要件数は検出したい差の大きさで決まる（0.03 を読むには233問）。**どれだけ増やすべきかを決めるにも、先に散らばりを測る必要がある。** 順序は変わらない。
- **同じ条件を複数回回して平均する。** この実装は決定的なので、同じ条件は何度回しても同じ値になる。散らばりは乱数ではなくチャンク境界の位置から来ており、平均では消えない。
