# ADR 0001: 評価セットをパイプラインより先に作る

- 状態: 採用
- 日付: 2026-09-21

## 背景

RAG を作るとき、自然な手順はパイプラインを組んでから精度を見にいくことだ。動くものが早く手に入り、達成感もある。

しかしその順序だと、評価セットを作る時点で既にパイプラインの出力を見てしまっている。結果として「今の実装が正解できる質問」に無意識に寄った評価セットができあがり、スコアは高く出るのに改善の判断には使えない。

## 決定

**評価セットと評価指標を、パイプラインの実装より先に作る。**

具体的には、以下の順で進める。

1. コーパスを選定する
2. 質問と正解根拠の対を 40〜60 件作る
3. 評価指標を定義し、なぜその指標かを文書化する
4. その後でパイプラインを実装する

## 理由

- 評価セットが先にあれば、実装の途中で「この質問には答えられないから評価セットを直そう」という誘惑が働いたときに、自分で気づける
- 何を良しとするかを言語化する過程で、要件そのものが明確になる。実際、この作業中に「答えられない質問を1割混ぜて棄権率を測る」という観点が出てきた。パイプラインを先に作っていたら、この観点は出なかった
- 評価が先にあると、実装は「スコアを出すための最小限」で済む。作りすぎを防げる

## 結果

- 評価セット作成に相応の時間がかかる。全体工数の 1/5 ほどを見込む
- 一方で、実装後の手戻りはほぼ無くなる想定
- 評価セットを後から変更した場合は、バージョンを上げて過去の結果と混ぜない運用が必要になる

## 備考

この判断は、実務でテスト戦略を立てるときの考え方をそのまま持ち込んだもの。
「テストを後から書くと、通るテストしか書かなくなる」のと同じ構図が、RAG の評価にもある。
